# راهنمای تولید محتوای MDX برای rootLab-theDoc

این فایل را به‌عنوان مرجع به هوش مصنوعی بدهید تا محتوای درسی سازگار با رندرر فعلی سایت تولید کند. فایل‌های درس در `src/content/` قرار می‌گیرند و با پسوند `.mdx` ذخیره می‌شوند.

> نکته فنی: با اینکه پسوند فایل‌ها `.mdx` است، سایت از کامپایلر عمومی MDX استفاده نمی‌کند. محتوا را یک رندرر Markdown سفارشی می‌خواند؛ بنابراین از JSX، import، کامپوننت React دلخواه، HTML سفارشی یا قابلیت‌های خارج از این راهنما استفاده نکن.

## قالب فایل و فراداده

هر درس با فراداده بین دو خط `---` شروع می‌شود. این نمونه را کپی کن و مقادیرش را متناسب با درس تغییر بده:

```yaml
---
title: "عنوان درس"
description: "توضیح کوتاه برای فهرست و جست‌وجو"
category: "Networking"
order: 10
published: true
updatedAt: "2026-10-23"
difficulty: "Beginner"
readTime: "5 min read"
tags: ["networking", "example"]
---
```

مقادیر `difficulty` را یکی از `Beginner`، `Intermediate` یا `Advanced` بگذار. فراداده‌خوان ساده است؛ آرایه‌ها را به شکل JSON مانند نمونه بنویس. وقتی `published: true` باشد، درس در سایت نمایش داده می‌شود.

## Markdown پشتیبانی‌شده

- تیترهای `#` تا `####`؛ تیترهای سطح ۱ تا ۳ در فهرست مطالب ظاهر می‌شوند.
- پاراگراف، فهرست شماره‌دار و بولت‌دار، نقل‌قول، جدول با ردیف جداکننده.
- `**متن ضخیم**`، `*متن ایتالیک*`، `` `کد درون‌خطی` `` و `[متن لینک](https://example.com)`.
- فرمول کوتاه درون‌خطی بین علامت دلار، مانند `$2^n$` (صرفاً نمایش متنی است، نه موتور تایپ‌ست ریاضی).
- بلوک کد حصاردار با زبان؛ برای نمونه `text`، `json`، `python` یا `bash`.

### نمونه جدول

| بخش | کاربرد |
| --- | --- |
| تیترها | ساختار درس و فهرست مطالب |
| کد | نمایش دستورها و نمونه‌ها |

## جعبه‌های راهنما

از بلوک‌های زیر برای برجسته‌کردن نکته استفاده کن. متن عنوان بعد از نام نوع اختیاری است و پایان بلوک باید تنها `:::` باشد.

:::note نکته
اطلاعات تکمیلی یا تعریف کوتاه.
:::

:::tip پیشنهاد
راه ساده‌تر یا بهترین روش.
:::

:::warning هشدار
محدودیت یا موردی که باید با دقت بررسی شود.
:::

:::danger خطر
پیامد جدی یا اقدام پرریسک.
:::

:::important مهم
نکته‌ای که برای ادامه درس ضروری است.
:::

## بخش بازوبسته‌شونده

`section` برای گروه‌کردن یک قسمت مفصل یا مرحله‌ای است. عنوان را داخل کوتیشن بنویس:

:::section title="تمرین: بررسی تنظیمات شبکه"
این متن و بلوک‌های Markdown داخل بخش نمایش داده می‌شوند.

```bash
ip addr
```
:::

## ترمینال تعاملی داخل درس

بلوک `terminal` دستورها را در شبیه‌ساز امن سایت نشان می‌دهد. هر خط را با prompt ثابت `student@rootlab:~$` بنویس. برای افزودن توضیح فارسی به یک دستور، بعد از ` | ` توضیح را بیاور:

:::terminal title="بررسی DNS شبیه‌سازی‌شده"
student@rootlab:~$ dig example.com | مشاهده پاسخ نمونه DNS
student@rootlab:~$ nslookup example.com
:::

همین قالب را می‌توان با کدبلاک `terminal` هم نوشت:

```terminal title="نمونه ترمینال"
student@rootlab:~$ help
```

ترمینال سایت واقعی نیست: فرمان‌ها فقط خروجی‌های ازپیش‌تعریف‌شده و داده‌های ساختگی را در مرورگر نمایش می‌دهند؛ پردازش سیستم‌عامل یا درخواست شبکه اجرا نمی‌شود. از دستورهای پشتیبانی‌نشده خروجی واقعی انتظار نداشته باش.

### فرمان‌های شبیه‌ساز

فرمان‌های رجیستری فعلی: `help`، `clear`، `ls`، `pwd`، `whoami`، `date`، `echo`، `cat`، `ping`، `nslookup`، `dig`، `curl`، `nmap`، `whois`، `uname`، `id`، `uptime`، `chmod` و `history`.

در متن درس فقط فرمان‌هایی را به‌شکل قابل اجرا پیشنهاد بده که برای هدف آموزشی مناسب‌اند. از تمرین‌ها بخواه خروجی را تحلیل کنند؛ ادعا نکن که اسکن یا درخواست واقعی انجام شده است.

## بلوک کد قابل ارسال به ترمینال

کدبلاک‌های `bash`، `sh` و `shell` دکمه اجرای شبیه‌سازی‌شده در ترمینال دارند. برای زبان‌های دیگر فقط دکمه کپی وجود دارد. اجرا محدود به رجیستری فرمان‌هاست.

```bash
dig example.com
```

از کدبلاک shell فقط برای دستورهای تک‌خطی مناسب شبیه‌ساز استفاده کن؛ اجرای چندخطی، pipe یا قابلیت عمومی shell را وعده نده.

## لینک به درس دیگر

برای لینک داخلی از مسیر `/lessons/` و slug درس استفاده کن. slug شامل مسیر دسته‌بندی است؛ نمونه:

## افزودن تصویر به درس

برای هر درس، پوشه‌ای با همان مسیر دسته‌بندی در `public/` بساز. مسیر پوشه بر اساس مسیر فایل درس، بعد از `src/content/` است؛ نام فایل درس را به مسیر تصاویر اضافه نکن.

![لوگوی پنگوئن لینوکس](forai-linuxImg.png "تصویر نمونه از پوشه public/youtube/linux")

برای نمونه، کنار درس `src/content/youtube/linux/file-permissions.mdx` تصویرها را اینجا قرار بده:

```text
public/
└── youtube/
    └── linux/
        └── permissions-diagram.png
```

سپس در متن درس از Markdown استاندارد استفاده کن. مسیر تصویر نسبت به پوشه متناظر در `public/` محاسبه می‌شود:

```md
![نمایش مجوزهای فایل در لینوکس](permissions-diagram.png "نمودار مجوزهای فایل")
```

متن داخل `[]` برای دسترس‌پذیری و زمانی که تصویر بارگذاری نشود استفاده می‌شود. عنوان داخل کوتیشن به‌عنوان کپشن زیر تصویر نمایش داده می‌شود. می‌توانی زیرپوشه هم بسازی، مثلاً `![نمودار](images/permissions.png)`. برای فایل در مسیر عمومی دیگر یا URL خارجی، از مسیر شروع‌شونده با `/` یا نشانی کامل `https://` استفاده کن. فرمت‌های معمول مرورگر مانند PNG، JPG، SVG و WebP قابل استفاده‌اند.

## قابلیت‌های رابط سایت

سایت تیترها را در فهرست مطالب استخراج می‌کند و درس‌ها در جست‌وجوی سراسری سمت کاربر نمایه می‌شوند. خود فایل MDX امکان فراخوانی این قابلیت‌ها را ندارد؛ از JSX یا API ساختگی برای بازکردن جست‌وجو، ذخیره bookmark یا تغییر تم استفاده نکن.

قابلیت‌های محصول شامل شبیه‌ساز ترمینال مستقل، جست‌وجو با `Ctrl+K` یا `Cmd+K`، نشانک‌گذاری، ثبت پیشرفت مطالعه، تم روشن/تیره، ناوبری قبلی/بعدی درس و فهرست مطالب است. این‌ها قابلیت‌های رابط سایت‌اند، نه کامپوننت‌های قابل‌درج در بدنه MDX.

## قواعد خروجی برای هوش مصنوعی

1. فقط نحو و بلوک‌های همین راهنما را تولید کن؛ JSX، import، تگ HTML، کامپوننت فرضی، تب، آکاردئون دلخواه، نمودار تعاملی یا اجرای واقعی کد ننویس.
2. فراداده YAML را ابتدای فایل کامل کن و slug پیشنهادی را از مسیر فایل دسته‌بندی بساز.
3. دستورهای ترمینال را آموزشی و مجاز نگه دار؛ خروجی شبیه‌سازی را صریحاً نمونه/ساختگی معرفی کن.
4. اگر نمایش موردنیاز با قابلیت‌های موجود ممکن نیست، آن را به صورت متن، فهرست یا جدول بیان کن و اعلام کن که نیاز به توسعه رندرر دارد.
