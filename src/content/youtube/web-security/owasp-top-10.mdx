# OWASP Top 10 Vulnerabilities Overview

The Open Web Application Security Project (OWASP) Top 10 is the globally recognized consensus standard for developers and security teams outlining the most critical security risks facing web applications.

## Summary of the Top 10 Categories

| Rank | Vulnerability Category | Core Risk | Primary Countermeasure |
| :--- | :--- | :--- | :--- |
| **A01** | **Broken Access Control** | Users acting outside intended permissions (IDOR, privilege escalation) | Deny by default; enforce server-side ownership checks |
| **A02** | **Cryptographic Failures** | Exposing sensitive data in transit or rest; weak ciphers | TLS 1.3, AES-GCM, Argon2id, avoid hardcoded keys |
| **A03** | **Injection (SQLi, Command)** | Hostile data interpreted as commands | Parameterized queries, ORMs, strict input validation |
| **A04** | **Insecure Design** | Architectural flaws, lack of threat modeling | Shift-left security, threat modeling, rate limiting |
| **A05** | **Security Misconfiguration** | Default credentials, verbose error stack traces, open S3 buckets | Automated hardening, disabling debug modes |
| **A06** | **Vulnerable & Outdated Components** | Unpatched third-party NPM/pip dependencies | Software Bill of Materials (SBOM), automated Dependabot alerts |
| **A07** | **Identification & Auth Failures** | Credential stuffing, brute-force, weak sessions | Multi-Factor Authentication, account lockout, robust session IDs |
| **A08** | **Software & Data Integrity Failures** | Insecure deserialization, unsigned CI/CD pipelines | Code signing, strict package lockfiles, subresource integrity |
| **A09** | **Security Logging & Monitoring Failures** | Incidents going undetected for months | Centralized SIEM, real-time alerting, immutable audit logs |
| **A10** | **Server-Side Request Forgery (SSRF)** | Server tricked into fetching internal metadata or LAN services | URL whitelisting, disabling cloud metadata IP (`169.254.169.254`) |

## Case Study: SQL Injection vs. Parameterized Queries

### Vulnerable Code (String Concatenation)
```javascript
// DANGEROUS: Concatenating raw user input directly into query string
const query = `SELECT * FROM users WHERE email = '${req.body.email}'`;
db.execute(query);
```
An attacker submits: `admin@corp.com' OR '1'='1` which causes the database engine to bypass authentication.

### Secure Code (Parameterized Query)
```javascript
// SECURE: Parameterized query sends SQL structure and data separately
const query = `SELECT * FROM users WHERE email = ?`;
db.execute(query, [req.body.email]);
```

The database treats `req.body.email` purely as literal string data, regardless of quotes or SQL keywords.

:::tip Defense-in-Depth
Never rely on a single layer of security. Pair parameterized queries with a Web Application Firewall (WAF), least-privilege database user permissions (so the app cannot execute `DROP TABLE` or read master tables), and encrypted backups.
:::
